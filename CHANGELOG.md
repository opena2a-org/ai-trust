# Changelog

## Unreleased

### Security

- **Scan summaries queued with contribution saved as on go once, to the registry the run uses, not also to `api.oa2a.org` ([#271](https://github.com/opena2a-org/ai-trust/issues/271)).** `check` and `audit` queued each summary with the contribute library's `scanResult`, which sends the queue on its own whenever it holds 10 or more events, and ai-trust passed it no registry URL, so those sends went to `https://api.oa2a.org`; the run then sent the queue again to its own registry, the `--registry-url` value, `https://api.oa2a.org` by default. With a recorder in place of fetch, sharing ten scans with a loopback registry URL posted the same ten summaries, with the contributor token, to `https://api.oa2a.org/api/v1/contribute` and to the loopback URL, as did sharing one scan with nine summaries already queued; sharing twenty-five posted batches of 10 to 25 summaries to `api.oa2a.org` sixteen times before the one batch to the loopback URL. ai-trust now queues each summary without that send, and the run sends the queue once, in one batch, to its registry.
- **`--registry-url` with a user name or password in it is refused before any request, and an error line prints a URL without them ([#232](https://github.com/opena2a-org/ai-trust/issues/232)).** `check`, `audit` and `batch` exit 1 with an error that names the option, the `user:password@` part and an example, and do not echo the value; with `--json`, `check` prints that error as a JSON object on stdout. A registry error that quotes a URL with `user:password@` in it prints `[redacted]` in their place in the `Error:` line and the `--json` `"error"` of `check --no-scan`, `batch` and `audit`, and in the `Registry lookup failed` line of `check`.
- **A key that a scanner finding quotes from the scanned files is masked in text and `--json` output ([#217](https://github.com/opena2a-org/ai-trust/issues/217)).** The pinned `hackmyagent` 0.33.2 puts the matched text of its `AST-CRED-001` "Credential Harvesting Pattern" finding in the finding's message, a key in that text included, while its `AST-CRED-003` finding prints the key it reports masked. On a test agent with `sk-` keys in its `system-prompts.json`, `check <name> --scan-path <dir> --all` printed a 46-character key in full in the `AST-CRED-001` message, in the text output and in `--json`. When ai-trust reads the scanner's report it masks credential-shaped values in the name, description, message and fix of each finding and in every string of an analyst finding's result (the AnaLM Analysis text of `check --analm`), and it masks them in the error of a scan that gives no report, which carries the scanner's standard error, with `--json` and without. A value is masked when it starts with one of the scanner's vendor prefixes (`sk-ant-api` and a digit, `sk-proj-`, `sk-`, `sk_live_`, `sk_test_`, `ghp_`, `gho_`, `ghs_`, `ghu_`, `github_pat_`, `hf_`, `glpat-`, `npm_`, `AKIA`, `AIza`, `xoxa-`, `xoxb-`, `xoxp-`, `xoxr-`, `xoxs-`, `SG.`) followed by the body the scanner requires after that prefix, when it has the shape of a JWT: three or more dot-separated base64url segments, the first starting with `eyJ` and no letter, digit, `_` or `-` right before it, or when it has no prefix and the scanner reads it as a credential all the same: a run of 40 or more `A-Z`, `a-z`, `0-9`, `+`, `=` and `_` characters between word boundaries in which some 40 characters in a row neither repeat a unit of 4 or fewer characters nor give one character more than 36 of their places. A prefix right after a letter or digit, as the `sk-` in `task-`, is not one. A masked value is printed as its prefix and one `*` for each further character, at most 16, the form in which `AST-CRED-003` prints a key, and a value with no prefix is printed as one `*` for each character, at most 16. The same run now prints that key as `sk-****************`. Through a stand-in scanner that quotes a file holding a FAKE `sk-` key and a 46-character FAKE value with no prefix in a finding, in two analyst findings and in the error of a failed scan, `check <name> --scan-path <dir> --no-deep --all` printed the key 7 times and the other value 8 times in text output, 2 and 3 times with `--json`, and each once in the error, with `--json` and without; it now prints neither. `--no-deep` scans of two test trees that hold keys print the same text and `--json` output as before. A value in none of these shapes, such as a password shorter than 40 characters with no prefix, is printed as the scanner wrote it. The scanner's own report still carries the key; that needs the same fix in `hackmyagent`.
- **The bundled scanner runs with your saved choices out of its reach and its own telemetry off, and ai-trust passes it every decision by flag ([#147](https://github.com/opena2a-org/ai-trust/issues/147)).** ai-trust runs `hackmyagent secure` and the scanner's `--version` check with `HOME`, `USERPROFILE`, `OPENA2A_HOME` and `XDG_CONFIG_HOME` in a new temporary directory that is removed after the run, with `OPENA2A_TELEMETRY=off` and `ORT_DISABLE_TELEMETRY=1` ([#218](https://github.com/opena2a-org/ai-trust/issues/218)), and without `ANTHROPIC_API_KEY`. The scanner reads no saved choice from `~/.opena2a/config.json` or `~/.hackmyagent/config.json` and writes none, sends no telemetry of its own and no scanned file to an LLM provider, and a downloaded package's scan no longer includes what the user keeps under `~/.openclaw`. ai-trust passes `--no-contribute` to every run, `--deep` or `--static-only`, and `--analm` when asked, and links `~/.nanomind` and `~/.opena2a/nanomind` into the temporary home of a deep scan, so the scan finds its classifier models where it did ([#276](https://github.com/opena2a-org/ai-trust/issues/276)). An end-to-end test runs `check --scan-path` and `audit --scan-missing` with the real scanner over every combination of saved choice, legacy scanner config and contribution flag, and fails on any request from the scanner that reaches its capture server. The test does not send two kinds of request there: the classifier model download a deep scan makes when no model is installed, which a local stub answers with a 404, and loopback requests to ports other than the stub's and the capture server's, which go through unchanged and which a deep scan makes to the NanoMind daemon.
- **Commands ai-trust prints for you to run quote a package name with shell syntax in it ([#141](https://github.com/opena2a-org/ai-trust/issues/141), [#218](https://github.com/opena2a-org/ai-trust/issues/218)).** A name with any character other than ASCII letters, digits and `_@%+=:,./-` is single-quoted in the `ai-trust check` commands of the Next Steps and the `npx hackmyagent check` command of the out-of-scope notice, in text and in the `--json` `nextSteps`.
- **A saved contribution value other than the boolean `true` is not consent ([#141](https://github.com/opena2a-org/ai-trust/issues/141)).** `config contribute status` reports a value in `~/.opena2a/config.json` that is not `true` or `false` as not set, and `check` and `audit` do not share a scan on it.
- **`audit --scan-missing` downloads the names your dependency file lists, not the names the registry answers with ([#137](https://github.com/opena2a-org/ai-trust/issues/137)).** An answer that matches no entry of the file, ignoring case for npm and after PEP 503 normalization for PyPI, is not downloaded. The npm download, which `check` also uses, refuses a name that is not an npm registry package name before npm runs, and runs `npm pack` with `--ignore-scripts`.
- **Scanning a PyPI package runs none of the package's code and does not need `pip` ([#123](https://github.com/opena2a-org/ai-trust/issues/123)).** ai-trust reads the release from the PyPI JSON API, downloads the file PyPI lists for it, refuses the file unless its SHA-256 matches the digest PyPI lists, and extracts it with `tar` or `unzip`. A name that is not a valid PyPI package name is refused before any request.
- **A dependency name that looks like an option, and a symlinked manifest in a downloaded package, are no longer acted on ([#123](https://github.com/opena2a-org/ai-trust/issues/123)).** The name is passed to npm after `--`, reading a downloaded package's version skips a manifest that is not a regular file, and the npm identity check refuses a `package.json` that is not a regular file.
- **Control characters in a registry answer are removed before text output ([#129](https://github.com/opena2a-org/ai-trust/issues/129)).** Text output replaces a run of tabs and line breaks with one space and removes the other control characters; `check --json` carries each string as the registry sent it, with control characters written as JSON escapes.
- **ai-trust runs the `hackmyagent` it pins, never one on `PATH`.** It runs the copy Node resolves for ai-trust, also through a symlinked `node_modules`, `npm link` or a Yarn Plug'n'Play cache, and refuses a copy Node finds only in one of its global folders (`NODE_PATH`, the home-directory module folders and `<prefix>/lib/node`).
- **Releases are built with `npm ci --ignore-scripts`, and the job that publishes to npm holds only the publish identity.** That job runs no checkout and no install, publishes the tarball the build job packed once its SHA-256 matches, passes `--registry` explicitly, and fails when npm shows no SLSA v1 provenance attestation for the version within five minutes.

### Added

- **`ai-trust config contribute on|off|status` saves and shows whether your scans are shared.** With `--json` it prints `{"contribute": true}`, `{"contribute": false}` or, when no choice is saved, `{"contribute": null}`. The consent messages, the contribution tip and `--help` name `ai-trust config contribute on|off`.
- **`check <name>@<version>` downloads and scans that version ([#221](https://github.com/opena2a-org/ai-trust/issues/221)).** For a tag or a range, the output names the version npm resolved it to, and `check pip:<name>@<version>` downloads that release from PyPI ([#224](https://github.com/opena2a-org/ai-trust/issues/224)). The registry lookup asks about the package `<name>`, the output notes that the registry's answer and score are the package's, not the version's, and `--json` carries `requestedVersion` and `answerScope: "package"`. `check skill:<name>@<version>` and `check mcp:<name>@<version>` ask the registry for the narrative of that version, and `check <name>@` is a usage error.
- **Each finding of a scan names its file and line, and `check --scan-path` adds a Verify command.** Text and `--json` name the file a finding is in, with its line when the scanner gives one, and `--json` carries the scanner's fix. Under `check --scan-path`, a finding with a file and a line prints a Verify command, a finding whose file is not in the directory is marked as not present, and a finding the scanner gave no fix says so.
- **`check --all` prints every finding**, and the line that counts the findings the text output leaves out gives that command.
- **`check --analm` says whether the scanner's analyst layer ran ([#178](https://github.com/opena2a-org/ai-trust/issues/178)).**
- **`check --json` carries more of what the text output shows.** A registry answer carries `communityScans`, and `scanStatus`, `lastScannedAt` and `securityProfile` (`criticalCount`, `highCount`, `knownCves`) when the registry returns them. A downloaded package's scan carries `checks` (static and semantic counts), the registry's answer as `registry`, a failed registry lookup as `registryError`, and the failed checks left out of its score as `notCounted` ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).
- **The scan output of `check` prints the registry's score beside the scan's when the two differ by more than 20 points.**
- **Each help screen ends with the documentation URL**, `Documentation: https://opena2a.org/docs/ai-trust`.
- **`check` and `audit` accept `--no-contribute`.** An explicit `--contribute` or `--no-contribute` answers for that run, whatever the saved choice.
- **`ai-trust --json telemetry on|off|status` prints JSON ([#177](https://github.com/opena2a-org/ai-trust/issues/177)).**
- **The published package includes the Apache-2.0 `LICENSE` file.**

### Changed

- **`batch --json` gives a name the registry does not have as its `name` and `"found": false` alone, a breaking change ([#276](https://github.com/opena2a-org/ai-trust/issues/276)).** The registry's answer for `nonexistent-xyz-999`, a name it does not have, carries `packageId` `00000000-0000-0000-0000-000000000000`, `trustLevel` 0, `trustScore` 0, `confidence` 0, `verdict` `"unknown"` and an empty `packageType` and `scanStatus`, and `batch --json` printed that answer, though trust level 0 is the level of a blocked package. A script that read `verdict`, `trustLevel` or `packageId` of such a result reads `found` instead. The text output, the exit code and `meta` do not change.
- **Bumped the pinned `hackmyagent` scanner `0.23.11` → `0.33.2`.** The pin stays exact and the scanner is still run as `hackmyagent secure --format json`, so scans report the checks, findings and scores of `0.33.2`. An install no longer holds a second, older copy of ai-trust and of the scanner: `0.7.6`'s lockfile resolved `ai-trust` `0.2.25` under the scanner and `hackmyagent` `0.17.11` under that. On a downloaded package (the default `check <package>` and `audit --scan-missing`), the score leaves out `DEP-001` and `SANDBOX-001`, next to the local-setup checks it already left out: npm never publishes the `package-lock.json` that `DEP-001` asks for, and the Dockerfile that `SANDBOX-001` asks for describes the consumer's deployment rather than the package. The output names the failed checks it left out under `Not counted`, `--json` lists them as `notCounted`, and `check --scan-path` counts them.
- **ai-trust needs Node.js 20.19 or a later 20 release, or 22.12 or later ([#215](https://github.com/opena2a-org/ai-trust/issues/215), [#244](https://github.com/opena2a-org/ai-trust/issues/244)).** `engines` is `>=20.19.0 <21 || >=22.12.0`, where `0.7.6` declared `>=18.0.0`, and the README names these releases. On another release, where the bundled scanner fails with `ERR_REQUIRE_ESM`, `check` and `audit` name the Node.js version instead of advising a reinstall.
- **Registry lookups allow 15 seconds per request and retry once when the request itself fails.** A trust or batch lookup that times out or fails on the network is retried once; an answer with an error status is not retried, and publishing a scan result never is. When the first attempt times out, a line on stderr says so before the second, and after two timeouts the error names the registry and the time both attempts took ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).
- **`check` prints its out-of-scope notice on stdout ([#218](https://github.com/opena2a-org/ai-trust/issues/218)),** for a library the registry classifies and for one recognized by name; the exit code is unchanged.
- **Commands of another OpenA2A CLI are printed in the `npx <package>` form.** `check` on a library points to `npx hackmyagent check <name>`, keeping the `pip:` prefix of a PyPI package ([#132](https://github.com/opena2a-org/ai-trust/issues/132)); the local-scan verdict names `npx hackmyagent secure --fix`; and a finding's `Fix:` line and the next-step and rotation commands of a `check skill:` or `check mcp:` narrative use the same form.
- **`--no-deep` limits `check` and `audit` scans to static checks.** The scanner runs with `--static-only`.
- **A shared scan sends no finding names or messages, and the scan ping needs the same consent as a contribution.** A contributed scan sends the package version. The scan ping (package name, verdict and score) is sent only when the scan is shared. Once consent is given, sharing prints nothing per scan ([#113](https://github.com/opena2a-org/ai-trust/issues/113)); `audit` does not ask again after you answer no to its question or run `ai-trust config contribute off` ([#139](https://github.com/opena2a-org/ai-trust/issues/139)), and does not ask under `--no-contribute`; and the share prompt and the contribution tip call shared results pseudonymous. `audit` still asks after an off saved by `opena2a config contribute off` when no choice was saved before it, and after a no saved by ai-trust 0.7.6 or an off saved by hackmyagent that ai-trust first finds with three or more scans counted; the contribution guide says so ([#141](https://github.com/opena2a-org/ai-trust/issues/141)).
- **`ai-trust --help` states whether usage telemetry is on or off and the saved contribution choice, and no longer calls usage telemetry anonymous.** `telemetry on` and `telemetry off` say the choice applies to ai-trust and hackmyagent, which share the config file ([#230](https://github.com/opena2a-org/ai-trust/issues/230)); under `OPENA2A_TELEMETRY=off`, `telemetry on` says the variable keeps usage telemetry off ([#141](https://github.com/opena2a-org/ai-trust/issues/141)), and `telemetry status` gives the steps that turn it back on ([#135](https://github.com/opena2a-org/ai-trust/issues/135)).
- **`check` is described as a command that scans every in-scope package by default ([#98](https://github.com/opena2a-org/ai-trust/issues/98), [#123](https://github.com/opena2a-org/ai-trust/issues/123)),** in its help, next-step hints and docs, and in the note it prints for `--scan-if-missing`; a package the registry classifies as a library gets the out-of-scope notice and no scan.
- **`audit` reads only a `package.json` or a requirements file.** It reads a file named `package.json`, a `.txt` file whose name contains `requirements`, a file named `requirements`, or a `.txt` file in a directory named `requirements` ([#185](https://github.com/opena2a-org/ai-trust/issues/185)), and refuses any other file, or a directory, before anything is looked up.
- **The `Checks` line of `check` reports the scanner's semantic count**, and no longer counts the semantic layer's `AST-*` and `SEM-*` records as static checks.
- **A registry answer says when it was scanned and what its counts stand for.** The header reads `scanned <age>` or `scan date not recorded`, and the last count above zero in the `Findings` line ends in `(details not returned)`, since the registry returns counts, not findings. An answer with a scan date under a scan status that is not a finished one says why no score is shown, and `not scanned` is printed for an answer with no scan date whose status names no scan ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).
- **`NO_COLOR` set to a non-empty value turns color off, and a set `FORCE_COLOR` keeps it on ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).**
- **The `audit` and `batch` Next Steps name the packages and the file they are for ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).** They give one command per package up to three, then a count; a requirements file's packages are cited as `pip:<name>`; `audit` does not offer `--scan-missing` again after it ran; and a run with no step left prints no Next Steps section.
- **The `audit` and `batch` table prints each package name whole when stdout is not a terminal ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).** On a terminal a shortened name ends in a whole character, not half of an emoji ([#198](https://github.com/opena2a-org/ai-trust/issues/198)), a package with no score shows `--`, and the columns line up under their headers.

### Fixed

- **A `--no-deep` scan writes nothing under `~/.nanomind` ([#276](https://github.com/opena2a-org/ai-trust/issues/276)).** ai-trust created `~/.nanomind` and linked it, and `~/.opena2a/nanomind` when present, into the scanner's temporary home for static scans and the scanner's `--version` check too, so the integrity event log the scanner writes when it starts, `~/.nanomind/integrity-events.jsonl`, was written to your home directory: in a new home, `check <name> --scan-path <dir> --no-deep`, `check <package> --no-deep` and `audit package.json --scan-missing --no-deep` each left that file there. ai-trust now creates `~/.nanomind` and links the two directories only for a deep scan, which loads its classifier model from them; for a static scan and the `--version` check the log stays in the temporary home and is removed with it. A deep scan still writes the log to `~/.nanomind`, beside the model it downloads. The `--json` output of the `--scan-path` scan and the text output of the `audit` scan are the same as before.
- **`--min-trust` refuses each value it does not take in the same words, naming the value, and the help gives its default as `(default: 2)` ([#276](https://github.com/opena2a-org/ai-trust/issues/276)).** `audit` and `batch` printed `--min-trust must be a whole number between 0 and 4, not 2.5` for `2.5` but `--min-trust must be a number between 0 and 4` for `5`, `-1`, `9` or `abc`; each value now gets `--min-trust must be a whole number between 0 and 4, not <value>`, on stderr after `Error:` or as the `"error"` of `--json`, with exit code 1 as before. An empty value is named as `""`, and a value with a space or a control character in it as a JSON string. Their help printed the default as `(default: "2")`.
- **`check <name> --no-scan --json` gives the next steps the text output prints ([#276](https://github.com/opena2a-org/ai-trust/issues/276)).** Its `nextSteps` held `npx hackmyagent secure <project-dir>`, a step with a placeholder in it that the text output does not print, after the `ai-trust check <name>` command. It now holds the commands of the text's Next Steps: `ai-trust check <name>` (`ai-trust check pip:<name>` for a PyPI package), then `ai-trust audit <file>` when the current directory holds a file `audit` reads.
- **The `Path forward` line of `check` projects the score that ai-trust's score formula gives once the critical and high findings are fixed, or prints no number.** The line added 15 points per critical and 8 per high finding to the score, up to 100, and did not count the findings that stay: `check <package> --no-deep` on a downloaded package whose one finding is a high printed `Path forward: 90 -> 98 by fixing 1 high`, while a downloaded package with no finding scores 100, and `check kitchen-sink --scan-path <dir> --no-deep` on a test tree that also has 25 medium findings and 1 low printed `Path forward: 0 -> 100 by fixing 30 critical + 48 high`. The projection is now the formula ai-trust already uses to rescore a downloaded package once it leaves out the local-setup checks (a failed finding weighs 25 when critical, 15 high, 8 medium, 3 low; the score is `round(100 * exp(-sum / 150))`), applied to the failed findings left once the critical and high ones are fixed. The line prints that number only when the same formula gives the scan's own score from its failed findings, within 1 point, and that score is above 0; otherwise it reads `Path forward: fix <counts>, then rescan to measure`. The same two commands now print `Path forward: 90 -> 100 by fixing 1 high` and `Path forward: fix 30 critical + 48 high, then rescan to measure`. Scores, trust levels, verdicts and exit codes are unchanged.
- **A `check` stopped by Ctrl+C, SIGTERM or SIGHUP during a scan removes its temporary directories and stops the `npm pack` or scanner it started ([#177](https://github.com/opena2a-org/ai-trust/issues/177)).** It left `ai-trust-scan-*` (the download) and `ai-trust-scanner-*` (the scanner's home) in the temporary directory, and after a SIGINT sent to ai-trust alone the scanner kept running. ai-trust now passes the signal on, waits up to 2 s for the child to exit (and kills it after that or on a second signal), removes the directories and ends by the same signal, so a shell still reports 130 for Ctrl+C.
- **`check --scan-path` names the directory without an internal prefix ([#177](https://github.com/opena2a-org/ai-trust/issues/177)).** A directory that does not exist prints `error: <dir> could not be read (ENOENT).` in place of `error: scanLocalPath: <dir> ...`, as does the `--json` `"error"`; the exit code stays 2.
- **A fix the scanner writes on several lines stays inside the finding's `│` gutter and prints once ([#177](https://github.com/opena2a-org/ai-trust/issues/177)).** Each later line is indented under the text after `Fix:`, and a later finding with the same fix prints `Fix: same as for <name> (<file>) above`. A fix of one line prints in full each time; `--json` is unchanged.
- **Text output names package types one way ([#177](https://github.com/opena2a-org/ai-trust/issues/177)).** The `check` header and the `batch` and `audit` TYPE column print MCP server, A2A agent, skill, AI tool, LLM and library, and a scan the scanner calls `mcp` prints MCP server on its Surfaces line and in its verdict, in place of `mcp server`, `mcp_server` and `This mcp looks safe to use.`. `--type`, the Type mismatch lines and `--json` keep the identifiers.
- **The `batch` and `audit` table gives the registry's verdict and scan age as `check` does ([#177](https://github.com/opena2a-org/ai-trust/issues/177)).** A registry `passed` verdict prints as PASSED, not SAFE, and a LAST SCAN column prints the age `check` prints (`233 days ago (stale)`), `today` for a package `audit --scan-missing` scanned, and `-` with no date.
- Text output prints a registry answer whose scan status is not a string, or whose trust level is not a whole number, instead of throwing a TypeError ([#238](https://github.com/opena2a-org/ai-trust/issues/238)).
- `audit` and `batch` say why they exit 2, and print the `meets minimum trust level` line only when they exit 0; `audit` names every dependency that makes it exit 2 because the registry does not have it.
- `check --no-scan` and `batch` name the registry and a next step when the registry request fails, and `audit` does when the registry does not answer ([#177](https://github.com/opena2a-org/ai-trust/issues/177)) or answers with an error status or a body that is not JSON ([#237](https://github.com/opena2a-org/ai-trust/issues/237)).
- `check` and `batch` refuse a `--type` value that is not a package type, and `batch --type` lists a package the registry has under another type as a type mismatch ([#177](https://github.com/opena2a-org/ai-trust/issues/177)).
- `audit` and `batch` refuse a `--min-trust` that is not a whole number between 0 and 4 ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).
- `batch` looks up a name given twice, or as an MCP shorthand and in full, once ([#230](https://github.com/opena2a-org/ai-trust/issues/230)).
- With `--json`, these print one JSON object on stdout: a target that names no package ([#183](https://github.com/opena2a-org/ai-trust/issues/183)), an out-of-range `--min-trust` or a request over 100 packages in `audit` and `batch` ([#191](https://github.com/opena2a-org/ai-trust/issues/191)), a failed registry request in `batch` ([#192](https://github.com/opena2a-org/ai-trust/issues/192)), a usage error such as a missing `check` name ([#230](https://github.com/opena2a-org/ai-trust/issues/230)), a `check --scan-path` whose scan fails ([#227](https://github.com/opena2a-org/ai-trust/issues/227)) and a `check` whose scanner cannot be started ([#235](https://github.com/opena2a-org/ai-trust/issues/235)).
- `check --scan-path` prints the whole error when its scan fails ([#234](https://github.com/opena2a-org/ai-trust/issues/234)), and how to run or reinstall the scanner, not the directory fix, when the scanner gives no report ([#226](https://github.com/opena2a-org/ai-trust/issues/226)).
- `check --scan-path` names the temporary directory when the scanner's temporary home cannot be created in it ([#161](https://github.com/opena2a-org/ai-trust/issues/161)), and `check --scan-path` and `audit --scan-missing` name it when that home can be created but not removed ([#168](https://github.com/opena2a-org/ai-trust/issues/168)), instead of saying to reinstall the scanner.
- `check --scan-path` on a directory with no file to read says there was nothing to scan, and keeps the score and findings of a directory whose files were found but could not be read.
- A scanner report larger than 1 MiB no longer fails the scan with `stdout maxBuffer length exceeded`; ai-trust reads a report of up to 128 MiB.

The score is now the scanner's, out of 100, and the passed and total counts include the checks that passed, read from the scanner's report.
- A scan that measured nothing is not shared ([#123](https://github.com/opena2a-org/ai-trust/issues/123)): one that read no file and found none it could not read, or one that ran no check and found nothing, the scans whose text output prints no score. ai-trust sends no scan ping, summary or per-check results for it.
